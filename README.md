# MiniCity

シムシティクラシック風の都市育成ゲーム（iOS / SwiftUI + SpriteKit）。
画像アセットを持たず、ドット絵はすべてコードから生成している。

ストアとホーム画面に出る名前は「ミニシティ」。`MiniCity` はターゲット名と
バンドルID（`com.shuyafukai.minicity`）に残っている内部の名前で、
App Store には英語名の `Minicity` が別の開発元ですでにあるため使えない。

## 動かす

```bash
cd /Users/shuyafukai/pj/minicity && xcodegen generate && open MiniCity.xcodeproj
```

Xcode を開かずにシミュレータで走らせるなら次のとおり。

```bash
cd /Users/shuyafukai/pj/minicity && xcodegen generate && xcodebuild -project MiniCity.xcodeproj -scheme MiniCity -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' build
```

## 遊びかた

なぞって引く道具（道路、送電線、撤去、公園）は、指を離しても確定しない。
なぞった線は半透明の予告として残り、画面下に出る「決定」を押して初めて敷かれる。
押さずに「やめる」を選ぶか、道具を持ち替えれば捨てられる。
なぞっている最中に行きすぎたら、指を離さずに来た道を戻ればその先が取り消される。
狙うのは触れた場所そのもの。照準は四方に腕を伸ばしてあり、指の外から
どのマスを狙っているかが見える。

一時期、指の腹に隠れるぶんを見越して少し上を狙わせていた。いまはなぞった線が
予告として残り、決定を押すまで確定しないので、確かめる役目は後ろの段に移っている。
前の段でずらすと、指と結果が離れている感じだけが残るのでやめた。

道具パレットの「移動」を選ぶと、1本指のドラッグで地図が動く。「調べる」も同じくドラッグで動き、
軽く叩いたときだけそのマスの中身を読む。建設の道具を選んでいるときは1本指はマスを塗る操作になり、
道路と送電線はなぞって引ける。拡大縮小は右下のつまみを上下になぞるか、⊕ ⊖ のボタン。
2本指ならどの道具でも地図を動かせて、つまめば拡大縮小もできる。
迷子になったら HUD の照準ボタンで都市の中心へ戻る。

シミュレータやリモートのパネル越しに触る場合、2本指のイベントがそもそも届かないことがある。
移動を1本指に、拡大縮小をつまみとボタンに割り当ててあるのはそのためで、操作はシングルタッチだけで完結する。

建設は、触れた瞬間ではなく指を離すか動かし始めた時点で確定する。
実機のピンチでは2本指が同時には着かず、1本目が着いた瞬間に建ててしまうと、
拡大しようとしただけで区画が建ったり、撤去で3x3が消えたりするため。

引ききるとマップの外側が見える。そこは海として塗ってあり、白い線が陸地の縁を示す。

はじめて遊ぶときは、起動すると地形を選ぶ画面から始まる。いきなり知らない地形に
放り出されると、何を見ているのか分からないため。保存された都市があるときは
そのまま続きから始まる。

税率と収支は予算画面で見る。HUD の資金額が入口で、枠と山括弧を付けて
押せることが分かるようにしてある。やり直したくなったら、その予算画面の
一番下の「新しい都市をはじめる」。
地形から作り直して1901年に戻る。戻せない操作なので確認をはさむ。
都市は自動保存されているため、アプリを閉じても続きから再開する。

道路は2種類ある。大通りは面した土地の値打ちを押し上げるが、敷く値段も維持費も高い。
同じ街でも街路を大通りにすると人口は 7,804 から 11,224 に伸びるが、
年収支は +1,168 から -1,369 に転じる。どこを表通りにするかを選ぶことになる。

立ち上げの手順は、発電所を1つ置き、道路を引き、その脇に住宅区と工業区を並べ、
送電線で発電所とつなぐ。区画どうしは互いに電気を通すので、線を引くのは最初の一本だけでいい。
電気か道路が足りない区画には稲妻とバツの印が出る。

## 中身

| 領域 | ファイル |
| --- | --- |
| マップとタイル | `Model/Tile.swift`, `Model/CityMap.swift` |
| 地形生成（川・湖・森） | `Model/TerrainGenerator.swift` |
| 道具と建設判定 | `Model/Tool.swift` |
| 都市の状態と1か月の更新 | `Sim/Simulation.swift` |
| 送電網（連結成分ごとの容量配分） | `Sim/PowerGrid.swift` |
| 通勤経路と交通量 | `Sim/Traffic.swift` |
| 公害・土地価値・犯罪・警察消防 | `Sim/Overlays.swift` |
| ドット絵の生成 | `Render/PixelCanvas.swift`, `Render/TileArt.swift` |
| マップ選択の下見 | `Render/MapPreview.swift` |
| SpriteKit の描画 | `Render/TileCatalog.swift`, `Render/CityScene.swift` |
| 画面 | `App/`, `UI/` |

描画は4層の `SKTileMapNode` を重ねている（地形・建物・送電線・不足の印）。
道路と送電線は隣接の有無から16通りの絵を選ぶので、つないだ形がそのまま見える。
3x3 の建物は 48x48 のドット絵を9枚に切って各タイルに割り当てている。

公害・土地価値・犯罪などは4マスを1セルにまとめた粗いマップ（30x25）で持ち、
拡散の計算量を 1/16 に落としている。

## シミュレーションの要点

需要 R/C/I は職と住のつり合いから作る。定数項を入れてあるので、
まっさらな都市でも工業と住宅から動き出し、人が入ってから商業の需要が立ち上がる。

区画が育つかどうかは業種ごとに別の式で決まる。

- 住宅：土地価値に強く反応し、公害と犯罪を嫌う
- 商業：住宅に近いが、公害への耐性がやや高い
- 工業：地価をほとんど見ず、注文（需要）があるかどうかで決まる

土地価値は、中心からの距離・水辺と緑・**その街区の発展度**から作り、公害と犯罪と渋滞で下がる。
発展度を入れてあるのが肝で、これがないとどの区画も最初のレベルで頭打ちになり、都市が動かなくなる。

育つしきい値は保つしきい値より高くしてある。この差のおかげで、
需要が少し揺れただけで建て直しが起きない。

## 公園と公害

公園は水辺・森と同じ「緑のアメニティ」として土地価値に足され、
さらに周囲の公害を吸収する（`Overlays.updatePollution` の公園の項）。
公害を直接減らせる手段は、いまのところ公園だけ。それ以外では、
発生源（工業区・発電所）を撤去するか離して建てるしかない。

最初の実装では、公園を建てると `tile.terrain` が上書きされ、
土地価値の計算が `terrain` だけを見ていたせいで、公園には何の効果もなかった
（森の上に建てると、森が持っていたぶんの効果を消すだけの逆効果ですらあった）。
見た目だけの飾りになっていたのに気づいて直した。

## バランスの確かめかた

シミュレーション部分は UIKit に依存していないので、ヘッドレスで長期挙動を試せる。

```bash
swiftc -O -o simtest MiniCity/Model/*.swift MiniCity/Sim/*.swift main.swift && ./simtest
```

成長判定の乱数は地形と同じ種から作ってあるので、何度走らせても同じ数字が出る
（変わるのは所要時間の行だけ）。バランスをいじったとき、差が変更のせいなのか
乱数のせいなのか迷わずに済む。

同じ数の区画（住宅88・商業44・工業44）を100年ぶん回すと、都市の作りかたで
こう分かれる。

| 都市の作りかた | 人口 | 最大地価 | 住宅の最高レベル |
| --- | --- | --- | --- |
| 工場を住宅の真隣に並べる | 1,152 | 90 | L3 |
| 住宅・商業・工業を離し、警察と消防を置く | 7,804 | 252 | L9 |
| さらに公園を敷き、警察と消防を行き渡らせる | 13,462 | 255 | L10 |

都市計画の良し悪しが7倍の差になって出る。

どの都市も 1910 年ごろに人口が動かなくなるが、これは行き詰まりではなく平衡である。
需要は職と住のつり合いから作るので、区画が育つと需要そのものが下がり、
その都市の作りに見合った高さで釣り合う。上の表は、その釣り合う高さが
作りかたでどれだけ変わるかを見ている。

## 絵の確かめかた

建物の絵はコードで生成しているので、アプリを起動しなくても画像に書き出して確認できる。
住宅・商業・工業それぞれの L0 から L10 までを横一列に並べた見本が出るので、
段が上がるごとに背がどれだけ伸びるかがその場でわかる。
住宅と商業の L6 以降は、アプリと同じように敷地の地面とタワーの2枚に分けて描いている。

```bash
swiftc -O -o scenegen MiniCity/Model/Tile.swift MiniCity/Model/TerrainGenerator.swift MiniCity/Model/CityMap.swift MiniCity/Render/PixelCanvas.swift MiniCity/Render/TileArt.swift tools/preview/main.swift && ./scenegen street.png && open street.png
```

アプリアイコンも同じ道具で書き出す。ゲームで使っているタワーのスプライトを
そのまま3本並べ、夜空と舗装だけを足した構図にしてある。

```bash
./scenegen --icon MiniCity/Resources/Assets.xcassets/AppIcon.appiconset/AppIcon-1024.png
```

書き出す PNG はアルファチャンネルを持たない（`CGImageAlphaInfo.noneSkipLast`）。
App Store はアルファ付きのアイコンを弾くため。

建物は見下ろした形で描く。奥行きは**真上**へ伸ばし、屋根（上面）と手前の壁の
2面だけを見せる。

以前は奥行きを右上へ45度に振っていたが、あの投影だと屋根が奥へ行くほど右へずれ、
`x + w + depth` が 48 を超えられない。区画は 48x48 なので、縦を埋めようとすると
横が痩せ、どう置いても建物のまわりに地面が大きく残ってしまう。真上へ伸ばせば
その制約が外れ、屋根を区画いっぱいに広げられる。

屋根が広くなるぶん、無地のままだと板に見える。幅と奥行きが一定以上のときは、
設備の小さな塊を散らして面に凹凸を作る。

土台になるのは `TileArt.box`（陸屋根）と `TileArt.house`（切妻屋根）で、
レベルごとの見た目は、その上に幅と高さと位置を並べているだけ。

**レベルの差は高さで見せる。** 棟数や細部を変えても、縮小すると読めない。
背の高さなら小さく描いても一目でわかる。段階は6つあり、住宅なら
平屋2棟 → 4棟 → 密集した集落 → 低層の集合住宅 → 中層 → 高層タワー と伸びていく。

育った瞬間には、その区画を一瞬だけ光らせる（`CityScene.flashUpgrade`）。
絵が差し替わるだけだと、目を離した隙に変わっていて気付けない。

配置には制約がひとつある。奥行きが右上へ伸びるので、`x + w + depth` が 48 を超えると
側面が切り落とされる。建物を足すときはここを確かめる。

壁の高さ（`height`）は屋根の奥行き（`depth`）より低く保つ。最初は高層ほど壁を伸ばしていたが、
比率が逆転して正面から見た絵に見えてしまった。屋根の面積が壁より広いくらいがちょうどよく、
見下ろした絵として読める。レベルの差は主にこの高さで付けるが、伸ばしすぎない。

描く順は奥の列から手前の列へ。手前の建物の影が奥の建物にかからないので、重なりが素直に見える。

## レベル1〜10と高層タワー

区画は10段階まで育つ（`Zone.maxLevel`）。1〜5は棟の集合として大きくなり、
6以降は低く広い土台の上に高層部が載る（`TileArt.towerSprite`）。

区画は置いた場所から `variant`（4通り）が決まり、これが形と色の両方を選ぶ。
形は偶奇の2通り、壁の色は4通りなので、同じレベルでも8通りの見た目になる。

高層部は1つの形に固定していない。同じレベルでも `variant` で別の形になる。

- **単塔**：土台の中央から細い塔が1本
- **ツイン**：2本を地面から直接立てる。高さを変えて片方を主役にする
- **セットバック**：段を重ねて上ほど細くする。足元が広く、いちばん重く見える
- **板状**：幅を取って奥行きを薄くした、団地のような塊

形を1つに絞ると、育った街区が同じ絵の繰り返しになって、引きで見たときの
輪郭が単調になる。区画ごとに `variant` が変わるので、同じレベルの街区が
並んでも輪郭がそろわない。

ツインだけは土台を持たない。1つの低層部を2本で共有する建物は現実には
ほとんどなく、載せると「大きな箱の上に塔が2本刺さっている」ようにしか
見えないため。土台のぶんの高さは塔の側に足して、他の形と背丈をそろえてある。

積み重ねの要点は、屋根が右上へ 45 度に伸びる平行四辺形だということ。
その上に何かを載せるには、奥へ入れた量ぶんだけ**原点を右へ・上へ同じ値で**送る。
ここが食い違うと足元が屋根の面から外れて浮いて見える（実際に一度そうなった。
x を `towerDepth / 2`、y を `podiumDepth / 3` と別々の値でずらしていた）。
上に載せる箱の奥行きも、下の段の奥行きに収める。深いと背面が奥の縁を突き抜ける。

影も高さに合わせる。`box` の影は既定では奥行きぶんしか伸びないので、
53px の塔が 8px の土台と同じ長さの影しか落とさず、質量が感じられない。
土台の影は塔まで含めた高さで伸ばし、スプライトの右端で断ち切られない長さで
頭打ちにしてある。

しきい値も6を境に刻みを強める。工業は地価の階段を登れないぶん、
住宅・商業より緩やかな刻みにしてある。

最上段まで登るには、土地価値を限界まで引き上げる必要がある。
都市が育つと需要は 0.15 前後で平衡するので、成長点の需要項は 16 点ほどしか出ない。
残りは地価から取るしかなく、L10 のしきい値 174 点に対して `landValue * 0.62` が
158 点、そこから公害と犯罪が引かれる。つまり L10 は、地価を振り切らせたうえで
公害と犯罪をほぼ削りきった街区にだけ立つ。

長らく L7 以上が一度も立たなかったのは、しきい値ではなく地価の側に原因があった。
都心の街区は発展度（`density`）が 490 に達するのに、地価への足し込みが 80 点で
頭打ちにされていて、地価が 202 で止まっていた。成長点は最良でも 134 点にしかならず、
144 点の L7 に構造的に届かない。上限を 140 点に上げると地価は 252 まで伸び、
よく計画された都市で L9 が、公園と警察・消防を厚く敷いた都市で L10 が立つ。

## 配色の決まり

壁の色は区画ごとに4通りに散らす（`TileArt.wallPair`）。住宅は生成り・タン・
灰・クレイ、商業は青・濃紺・青緑・スレート。2色に絞っていたころは、同じ
レベルの街区が並ぶと輪郭だけでなく色までそろい、引きで見ると1枚の壁のように
見えていた。

手つかずの土地は土の色にしてある。緑は森・芝生・公園にだけ使い、
「まだ何もない場所」と「人が手を入れた場所」を色で分ける。
土地をならすほど緑が減り、育つほど建物が増える、という読み方ができる。

区画には枠を残す。育つ前は破線、育ったあとは実線で、色は住宅が緑・商業が青・工業が黄、
警察と消防は灰色。建物が建ってからも、そこが何の区画かが一目でわかる。

区画の下地も種類ごとに変える。指定しただけの区画は整地しただけの土、
育った住宅は芝、商業は舗装、工業は砂利。下地だけ見ても区別がつく。

## 交通量の見せかた

渋滞している道路には、その場に小さな車を置く（`TileArt.trafficCars`）。
常時は出さず、しきい値を超えた区間にだけ出る。空いている道路は素の道のまま。

道路の形（接続方向のマスク）から車線の向きを決め、混みぐあいで2段階に分ける。
軽い渋滞は控えめな色の車を1台、詰まっている区間は目立つ色の車を2台、車線ごとに置く。

タイルの交通量（`Tile.traffic`）は見た目に出ない値として毎か月更新され、
`dirty` を通らない。電力や道路の不足を示す印と同じやりかたで、
道路タイルだけを自前で毎回たどって直す（`CityScene.refreshTraffic`）。
毎回すべてのタイルを見るのではなく、道路の添字を集合として持っておき、
そこだけをたどることで、大きな都市でも軽い処理に収めている。

別に「交通量」オーバーレイもあり、そちらは区域ぜんたいの混みぐあいを色の濃淡で見せる。
車のマークは道路そのものの実況、オーバーレイは俯瞰の統計、という役割分担になっている。

## スクリーンショットの撮りかた

ストアに載せる絵のために手で街を建てると何百回もタップすることになるので、
同じ計算をヘッドレスでやって、アプリが読むセーブデータとして書き出す。

```bash
swiftc -O -o savegen MiniCity/Model/*.swift MiniCity/Sim/*.swift tools/savegen/main.swift && ./savegen city.save 7
```

書き出したものをシミュレータの `Documents/city.save` に置くと、その都市から始まる。

```bash
xcrun simctl install <UDID> MiniCity.app
cp city.save "$(xcrun simctl get_app_container <UDID> com.shuyafukai.minicity data)/Documents/city.save"
```

初回に出る操作説明は `hasSeenHelp` で抑えられる。

```bash
plutil -replace hasSeenHelp -bool YES "$(xcrun simctl get_app_container <UDID> com.shuyafukai.minicity data)/Library/Preferences/com.shuyafukai.minicity.plist"
```

提出に要る寸法は 6.5 インチ（1284x2778）で、iPhone 12 Pro Max のシミュレータがちょうどその大きさになる。
いまの手元の Xcode には iPhone 11 Pro Max も XS Max も入っていないので、この機種で代える。

撮った生のスクリーンショットは、そのままでは並べても違いが伝わらない。
街の俯瞰は、寄っても引いてもオーバーレイを掛けても、スワイプする人には同じ絵に見える。
1枚ずつ見出しを載せて、何を見せているかを言う。

```bash
swiftc -O -o shotframe tools/shotframe/main.swift
./shotframe raw/city.png screenshots/01.png "区画を敷けば、街は育つ" "電気と道路が届いた区画から、人が住みはじめる"
```

選ぶ4枚は、街の俯瞰、オーバーレイ、マップ選択、予算画面。
画面の作りが違うものを選ぶ。同じ都市を寄り引きしただけの2枚は入れない。

撮った PNG はアルファチャンネルを落としてから出す。App Store Connect は
アイコンだけでなくスクリーンショットもアルファ付きを弾く。
`sips` にはアルファを外す指定がないので、CoreGraphics で
`noneSkipLast` として書き直す必要がある。

## 実績

集めた実績は `UserDefaults` に持たせてあり、都市を作り直しても消えない。
判定は `Simulation` の値を見るだけで済ませてあるので、途中経過を別に持たず、
セーブを読み直しても狂わない（`Model/Achievement.swift`）。

全34種類を、人口・発展・街づくり・経営・時代の5つに分けてある。
人口や資金の目標だけでなく、「最大公害 100 未満のまま人口 3,000」のように
街の作りを問うものを混ぜてある。数を伸ばすだけでは取れないものがあるほうが、
集める理由になる。

条件が増えるほど、判定のたびにタイルや区画を数え直すのが無駄になる。
1か月に一度 `CityStats` にまとめて数え、条件はその値を見るだけにしてある。

`id` は Game Center の実績IDとして使う。一度公開したら変えない。

Game Center はローカルの記録の写しにしてある（`App/GameCenter.swift`）。
サインインしていなくても、通信できなくても、集めた実績は端末の中で完結する。
サインインした時点で、それまでに取ったぶんをまとめて送る。

配点も `Achievement.swift` に持たせてある。出どころを1つにしておかないと、
IDの打ち間違いひとつで送信が黙って失敗する。

```bash
swiftc -O -o gcachievements MiniCity/Model/*.swift MiniCity/Sim/*.swift tools/gcachievements/main.swift
./gcachievements --list > ACHIEVEMENTS.md
```

同じ道具に鍵を渡せば、App Store Connect へ一括登録もできる。
すでにあるものは飛ばすので、実績を足したあとに何度でも流せる。

```bash
export ASC_KEY_ID=... ASC_ISSUER_ID=... ASC_KEY_PATH=...
./gcachievements            # 何をするかだけ出す
./gcachievements --apply    # 実際に登録する
```
